# 2026.241.0124 — fix: the setup launcher must not require the removed charly submodule

## Summary

The marketplace repo's `./setup` launcher is generated by this plugin, and it still `cd`-ed into
a nested `./charly` submodule. **That submodule was deliberately removed** — the refs downloader
initializes every declared submodule on fetch, so declaring one dragged the whole charly repo into
consumer fetch trees. This repo's own PR #2 and the marketplace repo's `deploy.yml` both record
that reasoning. The submodule went; the launcher that requires it did not.

So `./setup` and `./setup --check` have been **dead** ever since — the marketplace's local
regeneration entry point and its local drift gate both fail before doing anything:

```
$ ./setup --check
./setup: line 7: cd: ./charly: No such file or directory
exit=1
```

The published CI gate was unaffected (`deploy.yml` clones charly at a CI-time tag into `/tmp`),
which is why this went unnoticed: the gate that runs is not the launcher that was broken.

Two smaller staleness items from the same cutover, fixed here too: the generated header told the
reader to consult a `.gitmodules` that no longer exists, and `--out ..` only named the marketplace
back when charly was nested inside it.

**Fix.** Resolve a charly checkout from `$CHARLY_SRC`, defaulting to a sibling clone — the layout
the opencharly umbrella provides, and the one charly's `taskfiles/Skills.yml` already assumes from
the other side (`MARKETPLACE_DIR: {{.ROOT_DIR}}/../marketplace`). Both paths are passed absolute.
A missing checkout fails with an actionable message instead of a bare `cd` error.

**Why it survived a full cutover — the RCA that matters.** The single assertion covering the
launcher *required the broken string*:

```go
for _, want := range []string{`cd "$(dirname "$0")/charly"`, "drift --root . --out ..", ...}
```

The test suite was **defending the defect**. Correcting the emitter alone would have turned the
suite red and invited reverting the fix. So that assertion is corrected to the real contract, and
`emit_setup_test.go` now **executes** the launcher against a stub `charly` on `PATH` and asserts
the arguments it actually passes. A shape check on a string is what let a script nobody ran stay
broken through a cutover; the new tests run it.

**3. End-to-end against the real CLI and the real marketplace repo** — the emitted launcher laid

```

./setup: line 7: cd: ./charly: No such file or directory
exit=1

### 2. NEW launcher, CHARLY_SRC pointed at a real charly checkout
charly marketplace: marketplace drift: 1 generated artifact(s) are stale:
  plugins/setup
```

Case 2 is the point: the launcher **reached the drift gate and got a real verdict**, where the old
one could not start. That verdict is `stale: plugins/setup` and is *expected and correct* — the
binary in that run still carries the old emitter, so it regenerates the old launcher and correctly
reports the new one as drifted. It resolves once this lands and the marketplace regenerates from a
charly that pins it (see below). Case 3 shows the failure is now actionable.

## Rulebook compliance

- **R1** — root-caused before remediating: the cutover that removed the submodule (#2) is
  identified as the origin, and the reason it went unnoticed (CI clones charly itself; the broken
  path is only the local launcher) is established rather than guessed.
- **R5 — delete legacy completely.** This is the missing half of that cutover: the submodule was
  removed but its consumer was left behind. The stale `.gitmodules` header and the relative
  `--out ..` are removed in the same change.
- **R7 / R10** — the gate is run on the final committed tree with a clean worktree, and the new
  tests are shown to fail without the fix rather than merely asserted to cover it.
- **R3** — no second launcher shape is introduced; the one emitter remains the single source.

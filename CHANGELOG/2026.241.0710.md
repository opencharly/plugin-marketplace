# 2026.241.0710 — fix: advance MARKETPLACE_REF to the marketplace's current main head

## Summary of changes

`MARKETPLACE_REF` is the immutable commit the `check-marketplace` R10 bed clones the published
marketplace corpus at. It sat at `e8efdb15` (2026-08-23) while `opencharly/marketplace` `main`
had moved **18 commits ahead** — so the bed has been gating a six-day-old artifact and reporting
PASS while doing it. That is the exact failure mode the surrounding comments warn about: the
`var:` is the clone layer's cache key, so a stale value keeps passing *because* it is stale.

Most concretely, the corpus at the old pin still carried the broken `setup` launcher that
`opencharly/marketplace#238` has since fixed — so the bed could not have caught it, and would
not catch it today.

Concrete edit — `candy/plugin-marketplace/charly.yml`, both occurrences of the sha and nothing
else:

- line 47, `var.MARKETPLACE_REF` — the clone layer's cache key.
- line 80, the `marketplace-pinned-commit` check's `stdout.contains` literal — duplicated on
  purpose (a `check:` step's substitution does not resolve a candy `var:`; it would SKIP the step
  instead of asserting). The file's own comment requires both to move together, and they do here.

`e8efdb15` → `b89cc57247f35c0708029751e67dcb1d9a930d83`, the current `main` head.

## Change class

**candy/box-config** — one candy's `charly.yml`, two literal sha values. No Go source, no schema,
no CLI, no workflow, no new step or check. Single repo.

**Closes / relates to:** relates to `opencharly/marketplace#238` (merged — the setup-launcher fix
whose corpus this pin now actually reaches) and `opencharly/charly#440` (the repaired
`task skills:pin`, which found this class of staleness). No ordering dependency: #238 is already
merged, and this PR only advances a pointer to it.

**Breaking change + rollback:** none — no surface removed or renamed; a pinned sha advances to a
newer commit on the same branch's history (the old pin is a verified ancestor of the new one).
Rollback is a plain revert, which restores the previous sha. The one behavioral consequence is
intended: the bed now builds against the current corpus instead of a stale one, so it can now
FAIL on real corpus defects it was previously blind to.

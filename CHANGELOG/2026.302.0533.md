# 2026.302.0533 — fix(skills): the drift-gate section names the gate's script, not the instrument it stopped using

## Summary

Head `ce4016175a49a0619bf5a314fef7d839b6f025b4` — 1 file changed, 20 insertions(+), 5 deletions(-).

This repo's `marketplace` skill — the SOURCE the corpus refs list pins DIRECTLY, and the file the corpus copy, the docs mirror and the docs recipe page are all projections of — described the marketplace repo's drift gate as

> including UNTRACKED regenerated files (`git status --porcelain`, not just `git diff --exit-code`)

That was the gate's OLD instrument, and the attribution was wrong. The gate is the marketplace repo's `scripts/drift-gate.sh` — ONE implementation, run by `deploy.yml` on every PR and by the daily refresh on the tree its own PR commits — and it asks "did the tree move since the index was set": the working tree against the index (`git diff --quiet`), and the files in NO index at all (`git ls-files --others --exclude-standard`).

**And the old instrument was wrong FOR THAT TREE SHAPE.** `git status --porcelain` reports the INDEX column as well as the worktree column, and the refresh stages its regenerated corpus on purpose — so the index differs from HEAD by design, and a gate built on that comparison fails on the refresh job's tree shape, every time it runs there. Measured 2026-10-29 on the refresh's own tree with the pinned generator (charly `2026.296.2116`): a check built on it aborted with DRIFT on a tree that had not moved at all, listing the whole staged corpus.

That is a property of the INSTRUMENT on that tree shape, and not a claim about any run: the refresh ran NO gate before 2026-10-29 (it pasted deploy.yml's gate SOURCE into its body), so no refresh ever aborted on it. The sentence that turned the measurement into a false history is corrected in opencharly/marketplace#596 (squash `d074818`, tag `v2026.302.0520`), whose body is the erratum entry; the changelog entry it corrects is immutable, because it is the projection of a body at merge time.

So this body names the gate's script and its two callers, names the two halves the gate actually checks, and says plainly why the gate does NOT use `git status --porcelain`. The teaching the old parenthetical carried — that the gate catches UNTRACKED regenerated files and not only a diff — is unchanged and still true; only the command it named is not.

The marketplace repo's half of the fix — the shared gate script, its control, and the refresh job that RUNS the gate on the tree its PR commits — landed as opencharly/marketplace#594, and it lands FIRST: per R4 the code is fixed before the prose that describes it, and this file is the source every projection of the skill is generated from. The RCA that corrects the false counterfactual in that repo's published RCA landed as opencharly/marketplace#596, and this repo's half of the same finding is opencharly/plugin-marketplace#56.

Closes #56

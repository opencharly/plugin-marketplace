# 2026.241.1105 — refactor: the generator generates the marketplace and nothing else

## Summary of changes

Phase B of the approved cutover: **the generator generates the marketplace and nothing else.**

It had a second, unrelated job — writing charly's own harness config:

- `.claude/hooks/*` (one file per `hook:` entity) plus a chmod pass,
- a read-modify-write **merge** of `.claude/settings.json`,
- the R0 dispatcher spliced into `CLAUDE.md` / `AGENTS.md`,
- the `setup` launcher, whose only purpose is running generation *locally*.

That job is why `--root` had to be a charly checkout, and therefore why local generation, the
`setup` launcher, `task skills:sync`/`drift` and the harness-surface drift gate all exist.

Concrete edits (net **−513 lines**):

| File | Change |
|---|---|
| `emit_hooks.go` | **deleted** (incl. `mergeSettings`, `applyHookModes`) |
| `emit_dispatcher.go` | **deleted** |
| `emit_setup.go`, `emit_setup_test.go` | **deleted** |
| `generate.go` | `buildEmissions` loses its `root` param and error return; `applyHookModes` and the `setup` chmod removed; stale doc comment ("renders into the two trees") corrected |
| `prune.go` | the `.claude/hooks` wholesale-delete and the `setup` entry removed |
| `generate_test.go` | the two tests that asserted the deleted behaviour now assert its inverse |

**Safe because:** `hook:` entities are consumed by nothing but the deleted emitter; charly's
`.claude/hooks/*` and `.claude/settings.json` are already committed files in git (they simply stop
being rewritten); and nothing anywhere validates the dispatcher table. `opencharly/charly#448`
removed the dispatcher markers first, and `emit_dispatcher` skipped marker-less files — so the
emitter was already a no-op on them before this deletion.

The generated `marketplace/setup` becomes an orphan. It is deleted in the marketplace repo rather
than left behind a transitional prune entry (R5: no transitional path).

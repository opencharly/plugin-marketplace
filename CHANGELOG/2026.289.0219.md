The pin had **neither** symbol (`rc=1`); one path, one kind; and the only agent-aware side was the EMITTER — so an
agent's body had a writer to the corpus and nothing that could read it back from a file. That is the
live block this closes: `layer-charly-internals-extra` is the first W2 repo whose payload is mixed
(2 `skill:` nodes **and** 6 `type: agent` nodes), and HC forbids moving the two while leaving the six
inline in one repo and one file.

**What lands, as one cutover:**

1. **The file path per D8** — `extract` writes `.agents/agents/<name>.md`: ONE markdown file, no entry
   directory, no `references/` half, and no `skills:` lookup, because a `skills:` list is a list of
   SKILL trees. The branch sits *before* the tree lookup, not through it.
2. **The reader branch, with the skill branch's fail-loud contract** — `fillSkillFromFile` dispatches
   `type: agent` to `fillAgentFromFile`, which carries the same three loud rules the skill branch has:
   the file wins when it exists; an in-line body that differs from it is an error naming both; and
   **neither an in-line body nor a file is an error**. Silence in the last one is a published
   sub-agent subtracted from the corpus with no error — the failure class this migration has already
   paid for three times.
3. **The `extract` half, with the round-trip test that would have caught `plugin-marketplace#33`** —
   `extract → read → emit == the committed corpus`, asserted per node against the emitter's own
   projection, plus the byte assertion at EOF that no reading of the body can make.

Closes #34 — the cutover's issue, whose own *"Suggested shape"* is exactly the three points above — and
Closes #33, the one-byte EOF defect on this PR's own entry writer.

**And `#33` rides this cutover, deliberately.** The entry writers echoed `s.Content` verbatim while the
emitter and the reference writer two lines below both use `TrimSuffix(content, "\n") + "\n"`. So a repo
whose `content:` arrives without a trailing newline got an authored file differing from the projection
it publishes by exactly one byte, at EOF, on every skill of such a repo — `#33` measured 7 of 7 on
`pod-charly-versa` and nothing on a single-skill repo. One writer, one rule now, for both kinds.

**The chain, producer-first, and where this leg sits.** `spec` (`#256`) corrected the schema comment
that named the skills tree; `sdk` (`#420`) added `candywalk.ReadAgentFile`, tagged
**`v0.2026289.157`**, which this PR pins. The consumers this unblocks are filed, not promised:
**`layer-charly-internals-extra#21`** (2 skills + 6 agent nodes, filed by this cutover) and
**`pod-charly-automation#24`** (the node `#25` left inline for exactly this reason; commented). The
corpus side of it — this repo's pin in the marketplace refs list plus a regeneration — is the
`marketplace` repo's row, and it is the next step rather than a footnote.

# 2026.297.1419 — fix(pin): assert the 40-hex contains anchor is unique

## Summary

The validator's PASS on #52 carried one observation worth acting on, and this change
acts on it:

> Correctness of the `contains:` anchor depends on the pin's `contains:` being the first
> 40-hex `contains:` in the file ...; a future edit that adds an earlier 40-hex
> `contains:` would need the anchor tightened — worth a one-line note in the recipe, but
> not a blocker.

The `marketplace:pin` recipe's second step finds the pin's duplicated literal by its
ANCHOR — the `contains:` line — and takes the FIRST match. That is unambiguous today,
because exactly one 40-hex `contains:` line exists in `candy/plugin-marketplace/charly.yml`.
But the property was INCIDENTAL, not asserted: nothing checked it, so an edit that added
an earlier 40-hex `contains:` line would make the step compare the corpus head against
the wrong sha, and the resulting red would name neither the cause nor the file.

This change makes the precondition a CHECKED PROPERTY. A third check step counts the
40-hex `contains:` lines in the candy's file and requires exactly one, so the recipe
fails loudly — with a step that says what broke — if a future edit breaks the anchor's
uniqueness. The recipe's description now says why the anchor is read as the first match,
so the invariant is in prose as well as in the gate.

Files:

  (`pin-anchor-unique`) and the paragraph that explains the anchor.

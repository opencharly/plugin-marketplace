# 2026.289.1052 — fix(marketplace): report each artifact class under its own noun in `extract`

## Summary

**`marketplace extract` reports each artifact class under its own noun.** *One counter carried two classes while the verb's only output named one of them.*

```
before:  marketplace extract: %d skill(s) written under %s              <- one counter, one noun
after:   marketplace extract: %d skill(s) + %d agent(s) written under %s
```

*The split follows the two arms exactly as they already were — the agent branch (`writeAgentFile` then `continue`) increments the agent counter, the skill path increments the skill counter — so **no control flow changed and nothing new can be double-counted.** `extractSkills` returns both, `extract` sums both, the report line prints both.*

## The defect this closes (`plugin-marketplace#37`)

**Measured on two repos before the change, and the issue's diagnosis was verified at both `moved` sites rather than taken on trust:**

```
layer-charly-internals-extra   "8 skill(s) written"   for 8 bodies, ** 6 of them agents **
pod-charly-automation          "1 skill(s) written"   for 1 body,  ** 1 of them an agent **
```

*The second is the sharper case — 1 of 1, and the only line the verb emits. I measured it while landing that repo's last `type: agent` node.*

***Why this is not cosmetic:*** *`marketplace extract` is the verb a corpus-generation run reports through, so its output is evidence — and a number that mixes two nouns cannot be checked against either.*

# 2026.241.1043 — fix(marketplace.json): put description and version at top level per the spec

## Summary of changes

Phase A of the approved marketplace cutover — make `.claude-plugin/marketplace.json` conform to
the [Claude Code plugin-marketplace spec](https://code.claude.com/docs/en/plugin-marketplaces).

The spec defines `description` and `version` as **top-level** marketplace fields, and documents
`metadata` as the carrier for `pluginRoot`. This emitter nested both under `metadata`:

```go
Metadata struct {
    Description string `json:"description"`
    Version     string `json:"version"`
} `json:"metadata"`
```

so the published catalog has **no description and no version** as far as Claude Code is concerned.
It validates anyway — `metadata` is free-form — which is exactly why nothing caught it.

Concrete edits, both in `candy/plugin-marketplace/`:

- **`emit_marketplace.go`** — `description` and `version` move to top level (`omitempty`); the
  `metadata` block is dropped; `renames map[string]string` is added (`omitempty`) so a future
  plugin rename has the spec's supported path rather than silently orphaning installs.
- **`emit_marketplace_test.go`** (new) — three assertions pinning the shape: description/version
  are top-level and *not* under `metadata`; the spec's two required fields (`name`, `owner.name`)
  are present; `renames` stays omitted while empty.

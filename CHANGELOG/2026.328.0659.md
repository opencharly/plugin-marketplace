# 2026.328.0659 — feat(generator): retire individual SKILL cards, not only whole repos

## Summary

Part of opencharly/plugin-marketplace#64, and the missing control its RCA named: the corpus can now retire an individual **skill card**, not only a whole repo.

A stale skill does not always come with a retired repo. The thing a card describes can be consolidated or removed while its owner repo lives on, and its node then survives only in the owner's OLD tags. Measured at the owners' current heads:

- `pod-herdr` publishes `herdr-box`; `herdr` exists only in an old carrier.
- `distro-fedora` no longer carries `fedora-coder` or `fedora-test`.
- `layer-openclaw` publishes one `openclaw`; the four `openclaw-{desktop,full,full-layer,full-ml-layer}` variants exist only in old carriers.

Those seven were published to the corpus solely through stale subpath pins. opencharly/sdk#628 stops the stale whole-tree walks (this PR advances the sdk pin to its release, `v0.2026328.654`); this PR makes the retirement **explicit, reviewable and enforced**:

- `retired.cue` gains `retired_skills: ["<family>/<name>", …]`, validated against the SAME closed `#Retired` definition — an entry must be exactly `family/name`, and a typo fails the run.
- `readKinds` drops such a card wherever it comes from, so no future stale edge can republish it.
- The repo half (`retired:`) is unchanged.

The data itself (the seven, with reasons) lands in the corpus repo's `retired.cue`, and the docs generator will honour the same list.

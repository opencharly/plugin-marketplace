# 2026.322.1250 — fix(generate): wire public MCP servers only; a pod's localhost server never reaches the static config

Agent: claude-binding

## Summary

Closes #61. The generator wrote every declared `mcp_servers` entry into a family's static `.mcp.json` and referenced it from both plugin manifests. Every harness that loads the corpus therefore dialed the four pod endpoints at session start, whether or not the pod was running:

| family | server | url |
|---|---|---|
| coder | charly | `http://localhost:18765/mcp` |
| jupyter | jupyter | `http://localhost:8888/mcp` |
| selkies | chrome-devtools | `http://localhost:9224/mcp` |
| versa | marimo | `http://localhost:22718/mcp/server` |

A `claude -p` session in the umbrella reported all four `"status":"failed"` (opencharly/opencharly#1100).

By operator direction the generated MCP config carries **public servers only**:

- **One predicate**, `publicMCPServers`, decides the emission of `.mcp.json` and of the `mcpServers` reference in both `.claude-plugin/plugin.json` and `.codex-plugin/plugin.json`. A server qualifies when it is an `http` server whose URL host is not local (`localhost`, `*.localhost`, a loopback or unspecified address).
- **A family left with no public server** gets no `.mcp.json` and no reference.
- **The declarations stay as authored** in `opencharly/pod-charly-hooks`; only the emission is filtered. No `stdio` server is declared anywhere.
- **Prose** in `README.md` and the candy `description:` now states the rule.

| file | change |
|---|---|
| `candy/plugin-marketplace/emit_plugins_json.go` | `publicMCPServers` + `isPublicURL`; the three emitters use the one predicate |
| `candy/plugin-marketplace/emit_plugins_json_test.go` | new: the URL classification table, plus local-only / mixed / no-server families |
| `README.md`, `candy/plugin-marketplace/charly.yml` | the emission rule, stated where the outputs are listed |

The consumer leg follows producer-first: an opencharly/marketplace PR bumps `tools/marketplace-cli/go.mod` to this tag and regenerates, and its drift gate is the consumer-boundary check. The spec's schema comment is corrected in a parallel docs-only PR in opencharly/spec.
